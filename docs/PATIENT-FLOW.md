# 患者主流程（PATIENT-FLOW）· ANCA 相关血管炎 · M1 定稿

> 状态：✅ M1 定稿（与 [INTERACTION-DESIGN](INTERACTION-DESIGN.md) 同批，待 G1 签认）。
> 口径：主流程只描述"患者/家属实际会走的路"，不等于页面树；页面树见 INTERACTION-DESIGN §五。

## 一、主流程（首次进入 → 日常 → 复诊 → 回顾）

1. **首次进入**
   - 选择本机资料目录（不选不产生副作用；可跳过，业务页可用但数据不落盘）。
   - 建立病情档案：患者本人（必填：称呼/可选确诊年份）+ 家属照护者（可选，`author_role=caregiver`）。
   - 可选导入：既往出院记录、化验单、肾活检/影像报告（PDF/照片）。
2. **登记一次复查**
   - 看板「滴度与肾功」卡 →「记一次复查」。
   - AI 默认：拍化验单/口述 → 候选（PR3、MPO、肌酐、尿检、ESR/CRP；数值/单位/日期/实验室/报告原句）→ 逐项核对 → 确认入库。
   - 手工通道：「⋯ 更多」≤6 字段；数字用键盘组件。
   - 产物：`lab_reading` +1；滴度曲线与肾功/尿检分轨各新增一个点。
3. **登记一次复发事件（发生时）**
   - 看板「复发事件」卡 →「记一次事件」。
   - 记录日期、受累器官（可多选）、当时症状、确认依据原文（医生记录/检验/影像/病理）、就诊科室。
   - 产物：`relapse_event` +1；事件进入时间线与"事件回顾"。
   - **不判定**"这次是不是复发"；依据未填时显式留空（`NULL`），不生成"疑似"。
4. **登记用药变更（复诊后/换药时）**
   - 看板「治疗与用药」卡 →「记一次用药变更」。
   - 记录药名、剂量原文、途径、开始/结束日期、变更原因原文。
   - 产物：`treatment_version` +1；旧版本保留，新版本成为当前方案。
5. **日常副作用与随访**
   - 「激素副作用」卡 →「记一条副作用」：先选分节（骨与关节/糖代谢/感染/眼与其他），再记症状/检查/报告原文。
   - 「随访日历」→ 登记下次复诊的科室、日期、要带的材料；不推算"该查了"。
6. **复诊前**
   - 看板「下次复诊」卡 →「准备复诊」。
   - AI 按选定时间范围汇总**候选摘要**（只汇总事实）→ 逐条勾选 → 生成复诊摘要 + 问题清单。
   - 产物：`visit_summary` 1 份 + `question` N 条；可导出（private 默认不进导出）。
7. **复诊后回填**
   - 医生确认的内容（诊断原文、方案原文、下次复查时间）作为新版本回填；旧版本不覆盖。

## 二、家属代记通道（贯穿）

- 顶部主体切换「替家人记」：`recorder` 写家属，`subject` 仍是被照护者。
- 代记条目标识"家属记录"，原记录人不被覆盖；本人可补充/更正，形成版本链。
- private 条目：界面默认折叠、导出排除、AI 上下文排除（三出口同源）。

## 三、失败与恢复

| 情形 | 行为 |
| --- | --- |
| 拒收 AI 候选 | 零副作用：不落库、不改任何已有记录；可转手工补录 |
| 指标/单位识别不确定 | 候选标"待核对"，不自动入库；用户可改或拒收 |
| 同一天重复登记 | 提示"已存在同日期记录"，可选合并/新增，不自动覆盖 |
| 资料目录不可用 | 业务页可读缓存但不写；明确提示路径失效与重选入口 |
| 无原生会话 | 业务可用；AI 一键发送降级为"草稿未发送"提示，不假装接通 |
| 试验库未配置 | 显示"未配置/无法自动匹配"，不显示空结果当"没有试验" |

## 四、隐私与主体隔离

- 每条记录带 `author_role`（patient/caregiver）与 `visibility`（normal/private）。
- private 三出口同源过滤：界面列表、导出、Agent 上下文。
- 切换主体不串数据；档案切换后读模型按 `profile_id` 重算。
